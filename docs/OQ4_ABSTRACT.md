# OQ4: Short-Packet QPSK for Rapid Amateur-Satellite and Terrestrial Contacts

**Extended abstract — development draft**

**Prepared November 1, 2026 · Experimental OQ4 v1**

OQ4—O for OSCAR, Q for QPSK, and 4 for the four QPSK phase states—is an experimental narrowband digital mode being developed to combine substantially shorter transmission times with the practical weak-signal decoding ability operators value in FT4. Its primary attraction is speed: a complete OQ4 packet lasts approximately **2.523 seconds**, operating in **3.75-second alternating slots**. Initial operator observations in local noise-and-drift tests suggest FT4-like practical decodability while transmitting the message in roughly half the time. These observations motivate the design; they do not yet constitute a controlled measurement of relative sensitivity. **Our testing has not demonstrated a sensitivity disadvantage relative to FT4, and no fixed sensitivity penalty is assigned to OQ4.**

The immediate application is communication through existing amateur-radio linear satellite transponders, where a useful pass may last only a few minutes and successful exchanges must contend with changing frequency, fading, obstructions and limited opportunities to retry. Terrestrial operation is also an intended use. Development began with practical FT4 operation through RS-44 in OscarWatch, using that experience as a reference for the operating workflow. OQ4 preserves compact contact messages and familiar CQ, report and acknowledgment exchanges while exploring a different waveform, faster framing and receiver processing aimed at short, drifting signals. It is intended to work through an appropriate linear SSB signal path without requiring changes to satellite hardware.

OQ4 retains the established message and error-control foundations already used by FT4: a 77-bit packed message, the FT4 payload scrambling sequence, a 14-bit cyclic redundancy check and the same LDPC (174,91) forward-error-correcting code. The 91 message-plus-CRC bits are encoded into 174 transmitted data bits. This reuse provides a tested foundation for representing callsigns, locators, signal reports and short text, and lets the experiment concentrate on modulation, synchronization and decoding. The payload is a structured message representation rather than an unrestricted 77-bit chat channel. Sharing these coding components also does not make the modes interoperable: each requires its own waveform receiver. The common coding architecture follows the documented FT4/FT8 design. [FT4/FT8 protocol paper](https://wsjt.sourceforge.io/FT4_FT8_QEX.pdf)

The over-the-air distinction is substantial. **FT4 uses four-tone Gaussian frequency-shift keying; OQ4 uses coherent quadrature phase-shift keying.** OQ4 maps each pair of coded bits to the signs of the in-phase and quadrature components of a QPSK symbol. Its 174 data bits therefore require 87 data symbols, transmitted at 64 symbols per second. A root-raised-cosine pulse with a 0.25 roll-off factor shapes the signal. The resulting ideal data-waveform bandwidth is approximately 80 Hz, placing the design in a similar narrowband class to FT4. This is an ideal shaping bandwidth, not a verified occupied-bandwidth specification for every message, radio or transponder. Finite filter tails, burst edges and transmitter linearity must be included in practical spectrum measurements.

Each packet contains 32 known acquisition symbols, 87 data symbols and ten known pilot symbols arranged in five pairs. The pilot pairs are distributed through the data to support residual phase tracking. A 160-millisecond center-frequency reference tone precedes the shaped QPSK burst, and another follows it; both have tapered edges. Together with the pulse-shaping tails, these elements produce a 30,278-sample packet at the internal 12 kHz sample rate. The first reference helps locate a possible carrier, while the second supplies another frequency observation after the data has passed. Their frequency difference can support an estimate of average drift over the packet. The preamble and internal pilots then provide timing and phase information needed for coherent demodulation. These tones measure the received signal's combined offset and change; they do not independently identify satellite Doppler or remove oscillator and tuning errors.

The receiver searches the captured audio passband for candidate reference-tone pairs rather than requiring the operator to highlight the exact receive frequency. It correlates the known acquisition sequence, tests timing and carrier hypotheses, and evaluates linear and curved frequency trajectories. After downconversion and matched filtering, pilot-based phase estimates generate soft bit information for error correction. Both normal and spectrally inverted signal paths are considered. The implementation currently limits the number of candidates and hypotheses to keep processing bounded. Although the operating slots are short, decoding is not assumed to be instantaneous; capture buffering and background processing allow a complete packet to be retained while earlier work finishes.

Error recovery proceeds in stages. A fast belief-propagation LDPC decoder runs first. A bounded ordered-statistics fallback then examines a restricted set of reliability-based codeword alternatives. If those paths fail, code-assisted phase tracking uses extrinsic soft information from LDPC parity checks to refine residual phase and retry decoding. This feedback excludes each bit's own direct channel likelihood, uses confidence-weighted local smoothing and limits both the number and size of corrections. Its purpose is to exploit information already present in the received codeword when individual pilots or data symbols are noisy, without assuming the transmitted callsign or message. Decoder-to-carrier soft feedback is an established research approach; OQ4 applies a conservative experimental version to this short frame. A successful parity/CRC decode remains necessary before a message is displayed. [NASA/JPL soft-feedback synchronization research](https://ntrs.nasa.gov/citations/20090026416)

The practical timing advantage is straightforward. A 3.75-second grid provides sixteen global slots per minute, with eight transmit opportunities per station when the two stations use opposite parities. FT4 uses 7.5-second slots and approximately 5.04-second transmissions. OQ4 therefore offers twice as many nominal slot opportunities and roughly halves the duration of each transmission. A send-and-reply slot pair occupies 7.5 seconds rather than 15 seconds. These are scheduling opportunities, not a promise of twice as many completed contacts: successful decoding, operator actions, radio timing, retransmissions and acknowledgment exchanges still determine the actual QSO rate. [WSJT-X user guide](https://wsjt.sourceforge.io/wsjtx-main_en.html)

The first comparative evidence is encouraging but preliminary. In one local Decoder Lab configuration, the operator observed OQ4 decoding approximately 60–70% of transmissions while FT4 decoded approximately 10%, with signal and broadband-noise levels of −40 and −23 dBFS RMS and a drift rate changing from 0 to −6 Hz/s. Those percentages were operator estimates rather than results from a counted, seeded comparison, so they establish a useful development observation rather than a general performance ranking. The important working hypothesis is that **OQ4 can deliver FT4-like useful decoding behavior with markedly quicker packets**, particularly when frequency changes make longer transmissions harder to receive. A controlled head-to-head benchmark is still needed to quantify where that similarity holds, where either mode leads and how frequently each completes an exchange.

Separate reproducible tests measure improvements within OQ4 itself. Adding bounded ordered-statistics decoding increased correct recovery from 87 to 92 messages in a 144-packet synthetic full-waveform corpus, without losing previous successes or returning an incorrect payload. The corpus includes two packet-average SNR levels, three audio frequencies, timing and carrier offsets, and stationary, linear and curved frequency trajectories. Code-assisted phase tracking retained all 92 successes and improved controlled symbol-domain tests with residual phase distortion: 254 of 300 correct messages increased to 287 with positive phase excursions and to 278 with negative excursions. These phase-tracking gains isolate one receiver mechanism after synchronization; they are not additional RF-recording decodes or a comparison with FT4. The receiver also retains 19 expected signals in thirteen recorded-pass clips, and produced no decodes in 160 synthetic noise/interference windows. The recording includes local transmit bleedover and candidate downlink returns, so it does not independently confirm the propagation path of every recovered packet or establish a completed OQ4 satellite QSO.

OQ4 reports approximate data SNR in a 2,500 Hz reference noise bandwidth, using all 87 data symbols after CRC validation. Original observations are retained for reporting when phase feedback is used, so the feedback process does not itself inflate the signal report. The stronger reference tones are excluded from this data-SNR estimate. An OQ4 report and an FT4 report therefore should not be treated as an automatic sensitivity comparison simply because both are expressed in decibels. Comparative receiver thresholds require consistent signal-power definitions, noise bandwidths, channel conditions and decoder settings. At equal average packet power a shorter burst contains less total energy, but that accounting fact alone does not specify the relative sensitivity of these two implemented receivers. No measured OQ4-versus-FT4 sensitivity offset has yet been established.

The current prototype integrates the waveform and receiver into an OscarWatch window that reuses its FT4 contact sequencer, station settings, activity highlighting, audio service and PTT infrastructure. This gives operators a familiar workflow while leaving OQ4's modulation and receiver distinct. The engineering objective is to increase the number of useful, correctly decoded exchanges available during a short pass, while retaining a narrow signal and useful weak-signal operation. The next evaluation should measure correct packets and completed contacts under paired FT4/OQ4 trials, including nonlinear drift, fading, adjacent signals and real satellite paths. OQ4's present contribution is the combination of **short packets, FT4-derived message and coding foundations, and drift-aware coherent reception**, with initial local observations supporting further investigation of FT4-like decoding ability at a faster operating cadence.

## Comparison at a glance

| Property | FT4 | OQ4 experimental v1 |
| --- | --- | --- |
| Modulation | Four-tone GFSK | Coherent QPSK with RRC shaping |
| Message payload | 77 packed bits | Same message-packing foundation |
| Error control | CRC-14 and LDPC (174,91) | Same CRC/code, with its own receiver processing |
| Symbol rate | About 20.83 baud | 64 baud |
| Signal width | About 83.3 Hz nominal | About 80 Hz ideal shaped-data bandwidth; RF measurement pending |
| Packet duration | About 5.04 s | About 2.523 s, including reference tones |
| Alternating slot duration | 7.5 s | 3.75 s |
| Global slot opportunities per minute | 8 | 16 |
| Synchronization | Distributed FT4 Costas arrays | Known QPSK preamble, pilot pairs and two center-frequency references |
| Decoder relationship | Established mode with implementation-dependent decoder features | Separate experimental coherent receiver; shares message/FEC primitives |
| Practical weak-signal comparison | Reference mode | Initial local observations suggest similar useful decodability; no established relative sensitivity offset |
| Interoperability | Requires FT4 support | Requires OQ4 support; cannot be decoded as FT4 |

FT4 numerical parameters are from the [WSJT-X user guide](https://wsjt.sourceforge.io/wsjtx-main_en.html); synchronization and coding are described in the [protocol paper](https://wsjt.sourceforge.io/FT4_FT8_QEX.pdf). OQ4 parameters and results reflect the local implementation at commit `a38b9b0`. Bandwidth entries use different definitions and are not a claim of a measured percentage reduction. RRC-shaped QPSK also has a varying envelope, making transmitter linearity an important difference from FT4's nearly constant-envelope waveform.
